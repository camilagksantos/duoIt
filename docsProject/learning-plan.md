# Learning Plan: Inglês para Devs

Status: rascunho
Atualizado em: 2026-11-05

## 1. Objetivo

Estudar inglês técnico voltado ao dia a dia de um desenvolvedor: programação, reuniões, code review, documentação e comunicação técnica.

## 2. Nível de entrada

Intermediário. Já domina estruturas básicas (presente, passado, futuro, perguntas, negativas). O foco é introduzir termos específicos de TI dentro de estruturas simples, mas completas.

## 3. MVP: aprendizado de palavras

- Cada palavra ou expressão aparece em uma frase simples e completa.
- A frase mostra o termo em contexto de trabalho (ex.: "I opened a pull request to fix the login bug.").
- O aprendiz vê a palavra, o significado em português e o exemplo.
- A frase é sempre contextualizada no trabalho de um dev.
- O significado é o usado no contexto da frase, não uma tradução literal.
- Cada palavra aparece em apenas um submódulo. Revisão e repetição ficam para a fase de criação do conteúdo.
- Se a cobertura exigir, a meta de palavras de um módulo pode aumentar.
- Nesta fase não há áudio nem pronúncia.

## 4. Escopo de conteúdo

Esta tabela é a fonte dos módulos de vocabulário (5.16 a 5.18). Os termos serão distribuídos entre os submódulos na fase de criação.

| Tema | Exemplos de termos |
|------|--------------------|
| Daily e standup | yesterday, today, blocker, working on, finished |
| Reuniões | planning, retro, refinement, backlog, sprint, follow up |
| Code review | review, approve, request changes, nit, suggestion, merge |
| Pull requests e issues | pull request, branch, bug, ticket, commit, deploy |
| Programação | function, variable, parameter, return, refactor, dependency |
| Documentação | README, guide, setup, architecture, example |
| Comunicação informal | ask, check, update, sync, heads up |

## 5. Módulos

Cada módulo estuda uma estrutura gramatical ou um grupo de vocabulário. Cada módulo é dividido em submódulos de 20 a 50 palavras, agrupados por situação. O número entre parênteses é a meta de palavras do submódulo. Grupos fora dessa faixa devem ser divididos.

### 5.1 Revisão das estruturas básicas (~80 palavras)

Exemplo: "I'm working on the login page."

- Submódulo A: rotina de trabalho (~40): work on, start, continue, keep
- Submódulo B: tempo e prazos (~40): today, yesterday, tomorrow, deadline

### 5.2 Perguntas, negativas e auxiliares (~120 palavras)

Exemplo: "Did you run the tests?"

- Submódulo A: perguntas de esclarecimento (~40): what, how, why, how many
- Submódulo B: negativas de status (~40): didn't, haven't, isn't, not yet
- Submódulo C: verificação (~40): did you check, can you confirm, did it pass

### 5.3 Modais de sugestão e obrigação (~80 palavras)

Exemplo: "You should add a test."

- Submódulo A: sugestões (~30): should, could
- Submódulo B: obrigação e necessidade (~30): must, have to, need to
- Submódulo C: possibilidade (~20): might, may

### 5.4 Present perfect e past simple (~250 palavras)

Exemplo: "I've finished the PR." / "I finished it yesterday."

- Submódulo A: entregas concluídas (~50): finished, completed, shipped, released
- Submódulo B: verbos de código (~50): wrote, fixed, refactored, deleted
- Submódulo C: verbos de reunião (~50): discussed, agreed, decided, proposed
- Submódulo D: bugs e incidentes (~50): broke, crashed, rolled back, reproduced
- Submódulo E: verbos irregulares de trabalho (~50): built, sent, ran, found, chose

### 5.5 Gerúndio e infinitivo (~200 palavras)

Exemplo: "I want to refactor this function."

- Submódulo A: verbos seguidos de gerúndio (~50): avoid, consider, suggest, finish
- Submódulo B: verbos seguidos de infinitivo (~50): want to, hope to, ask to, expect to
- Submódulo C: verbos com as duas formas (~50): like, love, hate, prefer
- Submódulo D: expressões de responsabilidade (~50): in charge of, responsible for

### 5.6 Voz passiva (~200 palavras)

Exemplo: "The bug was fixed."

- Submódulo A: particípios de código e testes (~50): reviewed, tested, configured
- Submódulo B: particípios de bugs (~50): reported, resolved, closed, verified
- Submódulo C: particípios de processo (~50): approved, scheduled, assigned, prioritized
- Submódulo D: particípios de documentação (~50): documented, updated, described

### 5.7 Condicionais (~100 palavras)

Exemplo: "If the build fails, I'll roll back."

- Submódulo A: condicional zero, fatos e processos (~30): if, whenever, unless
- Submódulo B: condicional primeiro, riscos e planos (~35): fails, times out, gets stuck, stops
- Submódulo C: condicional segundo, hipóteses (~35): would, were, improve

### 5.8 Discurso indireto e conectores (~150 palavras)

Exemplo: "He said the deploy was delayed because of a bug."

- Submódulo A: verbos de relato (~40): said, asked, mentioned, confirmed
- Submódulo B: conectores e expressões de causa (~35): because, since, due to
- Submódulo C: conectores de contraste (~35): although, however, but
- Submódulo D: conectores de sequência (~40): so, then, after that, finally

### 5.9 Present perfect continuous (~80 palavras)

Exemplo: "I've been debugging this for two hours."

- Submódulo A: duração de trabalho (~40): for, how long, all day, so far
- Submódulo B: atividades contínuas (~40): debugging, waiting, investigating

### 5.10 Orações relativas (~120 palavras)

Exemplo: "This is the function that validates the input."

- Submódulo A: pronomes relativos de pessoa (~40): who, whom, whose
- Submódulo B: relativas que definem coisas (~40): that, which
- Submódulo C: relativas de lugar e tempo (~40): where, when

### 5.11 Artigos e substantivos incontáveis (~80 palavras)

Exemplo: "Can you send me the feedback?"

- Submódulo A: artigos com termos de TI (~40): a, an, the
- Submódulo B: substantivos incontáveis de TI (~40): feedback, code, information, documentation

### 5.12 Futuro para planos (~100 palavras)

Exemplo: "I'll open the PR tomorrow." / "We're going to release on Friday."

- Submódulo A: decisões na hora e promessas (~30): will, I'll
- Submódulo B: planos e intenções (~30): going to, be about to
- Submódulo C: agenda com present continuous (~40): I'm meeting, the call starts at 3

### 5.13 Hedging e polidez (~100 palavras)

Exemplo: "I think we could simplify this part."

- Submódulo A: suavizar uma opinião (~40): I think, maybe, I guess, I'm not sure
- Submódulo B: pedir com educação (~30): would you mind, do you think, I wonder if
- Submódulo C: discordar com educação (~30): I see your point, I'm afraid, I'd rather

### 5.14 Phrasal verbs de TI (~150 palavras)

Exemplo: "Let's set up a call to sync up on the release."

- Submódulo A: colocar algo em funcionamento (~40): set up, roll out, spin up
- Submódulo B: concluir e entregar (~40): wrap up, hand off, sign off, clean up
- Submódulo C: investigar e entender (~35): figure out, look into, dig into, track down
- Submódulo D: coordenar e acompanhar (~35): sync up, follow up, catch up, pick up

### 5.15 Collocações de TI (~150 palavras)

Exemplo: "I'll open a PR and add a test."

- Submódulo A: verbos com PR e branches (~40): open a PR, push a commit, create a branch
- Submódulo B: verbos com bugs e tickets (~40): log a bug, add a test, file a ticket
- Submódulo C: verbos com revisão e decisão (~40): leave a comment, make a decision, request a change
- Submódulo D: verbos com entregas (~30): cut a release, solve a conflict, reopen a ticket

### 5.16 Vocabulário de processo e reuniões (~150 palavras)

- Submódulo A: rotina de daily (~40): daily, standup, blocker, update
- Submódulo B: planejamento (~30): planning, refinement, backlog
- Submódulo C: agile e cerimônias (~30): retro, sprint
- Submódulo D: reuniões e acompanhamento (~50): meeting, agenda, action item, next steps

### 5.17 Vocabulário de código e PRs (~150 palavras)

- Submódulo A: substantivos de código (~50): function, variable, parameter, dependency
- Submódulo B: substantivos de PR e issues (~50): pull request, branch, commit, ticket
- Submódulo C: termos de revisão (~50): nit, suggestion, merge, LGTM

### 5.18 Vocabulário de documentação e comunicação (~100 palavras)

- Submódulo A: documentação (~40): README, guide, setup, architecture, example
- Submódulo B: pedidos e avisos (~30): ask, heads up
- Submódulo C: canais e chamadas (~30): Slack, quick call

## 8. Hierarquia e liberação

Estrutura de três níveis:

- **Módulo:** estrutura gramatical (seção 5), na ordem da seção 7.
- **Grupo de palavras:** cada submódulo da seção 5 é um grupo de palavras, com a meta indicada. Cada grupo tem seus próprios exercícios.
- **Exercícios:** cada grupo tem até 4 tipos. O primeiro é **Cards** (flashcards com repetição espaçada, FSRS). Os outros 3 tipos entram depois.

Regras de liberação:

1. O primeiro grupo com palavras começa liberado. Grupos sem palavras aparecem como "Em breve" e não travam a sequência.
2. Dentro de um grupo, os exercícios liberam em sequência. O tipo 2 só abre depois que o Cards for concluído. O tipo 3 só abre depois do tipo 2, e assim por diante.
3. Concluir o Cards significa responder todos os cards do grupo pelo menos uma vez.
4. Um exercício concluído continua disponível para revisão. Concluir o Cards não bloqueia o Cards.
5. O grupo seguinte libera quando todos os exercícios do grupo atual forem concluídos.
6. Tipos de exercício ainda não disponíveis não bloqueiam a sequência. Enquanto um tipo não existir, a liberação segue só pelos tipos existentes.

Concluído e dominado são coisas diferentes:

- **Concluído:** todos os cards do grupo foram respondidos pelo menos uma vez. Mostra que o grupo foi visto.
- **Dominado:** todos os cards do grupo têm intervalo de 21 dias ou mais. Mostra que a palavra foi aprendida.

A liberação do grupo seguinte depende de concluir. O domínio aparece no progresso.
